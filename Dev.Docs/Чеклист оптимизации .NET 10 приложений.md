# Чеклист оптимизации .NET 10 приложений

Комплексный чеклист для микросервисов и консольных приложений, охватывающий ключевые области производительности: latency, throughput и потребление памяти.

---

## 1. Native AOT оптимизации

### Конфигурация проекта
- [ ] **`<PublishAot>true</PublishAot>`** — включить AOT-компиляцию. Уменьшает размер до ~1 MB, startup в 2 раза быстрее
- [ ] **`<IsAotCompatible>true</IsAotCompatible>`** — для библиотек, включает анализ совместимости на этапе сборки
- [ ] **Тестировать с AOT на ранних этапах** — проблемы сложнее исправить позже

### Атрибуты совместимости
- [ ] **`[RequiresDynamicCode]`** — помечать методы с `Reflection.Emit`, `Type.MakeGenericType`. Предупреждает потребителей API
- [ ] **`[RequiresUnreferencedCode]`** — для методов с рефлексией, которая может сломаться при trimming
- [ ] **`[DynamicallyAccessedMembers]`** — указать какие члены типа сохранить. Позволяет безопасно использовать `Activator.CreateInstance`
- [ ] **`[UnconditionalSuppressMessage]`** — для подавления предупреждений, когда код безопасен

### Альтернативы рефлексии
- [ ] **Заменить `Type.GetType(string)`** на generic-методы с известными типами
- [ ] **Заменить `Activator.CreateInstance`** на фабрики или source generators
- [ ] **Заменить `Enum.GetValues(Type)`** на `Enum.GetValues<TEnum>()`
- [ ] **Заменить `Expression.Compile()`** на делегаты или source generators

### Source generators вместо рефлексии
- [ ] **System.Text.Json** — `[JsonSerializable]` вместо рефлексии сериализатора
- [ ] **Logging** — `[LoggerMessage]` вместо runtime-парсинга шаблонов
- [ ] **Configuration binding** — `<EnableConfigurationBindingGenerator>true` для AOT-совместимой привязки
- [ ] **Regex** — `[GeneratedRegex]` для compile-time регулярок
- [ ] **DI** — рассмотреть Jab, Pure.DI для AOT-friendly контейнеров

## 2. C# 13/14 и .NET 10 фичи для производительности

### params Span (C# 13)
- [ ] **`params ReadOnlySpan<T>`** — zero-allocation для variadic методов. До 7x быстрее чем массивы
- [ ] **Переписать hot-path методы** с `params T[]` на `params ReadOnlySpan<T>`
- [ ] **Учесть breaking change** — expression trees не поддерживают ref struct

### Semi-auto properties (C# 14)
- [ ] **Использовать `field` keyword** — `set => field = value ?? throw` вместо backing field
- [ ] **Сокращает boilerplate** для валидации в property setters

### FrozenDictionary / FrozenSet (.NET 8+)
- [ ] **Использовать для lookup tables** — конфигурация, справочники, кеши. ~50% быстрее чтение
- [ ] **НЕ использовать для изменяемых данных** — создание в 228x медленнее чем List
- [ ] **`ToFrozenDictionary()` / `ToFrozenSet()`** — вызывать один раз при старте

### SearchValues<T> (.NET 8+)
- [ ] **Использовать для частых поисков** — 4-7x быстрее `IndexOfAny`. SIMD-оптимизация
- [ ] **Создать static readonly поле** — `SearchValues.Create("ABCabc0123")` парсится один раз
- [ ] **В .NET 9: поиск по строкам** — `SearchValues.Create(["Alice", "Bob"])` для multi-string search

## 3. Работа с памятью

### Span<T> и Memory<T>
- [ ] **`Span<T>` для синхронного кода** — stack-only, быстрее, zero-copy slicing
- [ ] **`Memory<T>` для async операций** — можно хранить в полях, передавать между await
- [ ] **`ReadOnlySpan<T>` для read-only** — строки автоматически конвертируются через `.AsSpan()`
- [ ] **Парсинг без аллокаций** — `int.Parse(span)`, `DateTime.TryParse(span, out _)`

### ArrayPool<T>
- [ ] **`ArrayPool<T>.Shared.Rent(size)`** — для временных буферов >1KB. До 850x быстрее new[]
- [ ] **ВСЕГДА Return в finally** — утечка памяти при exception
- [ ] **`clearArray: true`** — для чувствительных данных (пароли, токены)
- [ ] **НЕ использовать после Return** — данные могут быть перезаписаны
- [ ] **Учесть что размер может быть больше** — `Rent(100)` может вернуть 128 элементов

### MemoryPool<T> и ObjectPool<T>
- [ ] **`MemoryPool<T>.Shared.Rent()`** — когда нужен `IMemoryOwner<T>` для async
- [ ] **`ObjectPool<StringBuilder>`** — для StringBuilder в hot path
- [ ] **`RecyclableMemoryStreamManager`** — для MemoryStream pooling

### stackalloc
- [ ] **Использовать для буферов <256 байт** — `Span<byte> buf = stackalloc byte[64]`
- [ ] **НЕ использовать в циклах** — риск stack overflow (CA2014)
- [ ] **НЕ использовать user-controlled размер** — проверять `length <= MaxSize`
- [ ] **Hybrid pattern** — stackalloc для малых, ArrayPool для больших размеров

### ref struct и scoped
- [ ] **`ref struct`** — для типов содержащих Span (не может быть в heap)
- [ ] **`scoped` параметр** — гарантирует что Span не "убежит" из метода
- [ ] **ref returns** — для возврата ссылки без копирования структур

### Избегание аллокаций
- [ ] **Boxing** — использовать generic методы `void Log<T>(T value)` вместо `object`
- [ ] **Closures** — `static` лямбды где возможно, передавать state через параметр
- [ ] **LINQ в hot path** — заменить на foreach с ручной фильтрацией
- [ ] **String interpolation** — в .NET 6+ не вызывает boxing, но избегать в log calls
- [ ] **struct vs class** — struct для ≤16 байт, immutable, без boxing

## 4. EF Core оптимизации

### Compiled Queries
- [ ] **`EF.CompileQuery` / `EF.CompileAsyncQuery`** — 10-15% быстрее для частых запросов
- [ ] **Хранить как static readonly** — компиляция один раз при старте
- [ ] **НЕ использовать для динамических запросов** — только fixed query shape

### Tracking поведение
- [ ] **`AsNoTracking()`** — для read-only. 20-40% быстрее, меньше памяти
- [ ] **`AsNoTrackingWithIdentityResolution()`** — когда есть Include, предотвращает дубликаты
- [ ] **Default NoTracking** — `UseQueryTrackingBehavior(NoTracking)` в OnConfiguring

### Split Queries
- [ ] **`AsSplitQuery()`** — для запросов с несколькими Include. Избегает Cartesian explosion
- [ ] **Бенчмарк показал** — с collections: 35ms vs 200ms, 8MB vs 47MB памяти
- [ ] **Учесть consistency** — split queries не атомарны, использовать транзакции если нужно

### Bulk Operations (EF Core 7+)
- [ ] **`ExecuteUpdateAsync`** — bulk update без загрузки. `Where().ExecuteUpdateAsync(s => s.SetProperty(...))`
- [ ] **`ExecuteDeleteAsync`** — bulk delete одним SQL. До 10x+ быстрее чем RemoveRange + SaveChanges
- [ ] **Обходят Change Tracker** — entities в памяти не обновляются
- [ ] **В транзакции с SaveChanges** — если комбинируете с обычными операциями

### DbContext Pooling
- [ ] **`AddDbContextPool<T>()`** — 5.5x быстрее, 10x меньше памяти в high-throughput
- [ ] **`AddPooledDbContextFactory`** — для background services и параллельных операций
- [ ] **poolSize: 128-256** — настроить под нагрузку

### Загрузка данных
- [ ] **Projection вместо полной entity** — `Select(x => new { x.Id, x.Name })`
- [ ] **Избегать Lazy Loading** — скрытый N+1, отключить в production
- [ ] **Keyset pagination** — `Where(x => x.Id > lastId).Take(pageSize)` вместо Skip/Take

## 5. Кеширование

### IMemoryCache
- [ ] **`GetOrCreateAsync`** — atomic-подобный паттерн, но factory может выполниться несколько раз
- [ ] **`AbsoluteExpiration` + `SlidingExpiration`** — комбинировать для оптимального TTL
- [ ] **`SetSize` + `SizeLimit`** — контролировать размер кеша

### HybridCache (.NET 9+)
- [ ] **Заменить IMemoryCache** — встроенная защита от stampede, L1+L2 из коробки
- [ ] **Tag-based invalidation** — `RemoveByTagAsync("category:5")` для групповой инвалидации
- [ ] **Автоматическая сериализация** — для distributed cache

### Cache Stampede Prevention
- [ ] **HybridCache** — автоматическая защита
- [ ] **SemaphoreSlim для IDistributedCache** — double-check locking pattern
- [ ] **Lazy<T> pattern** — `GetOrCreate` возвращает `Lazy<T>`, value достается один раз
- [ ] **Probabilistic early expiration** — обновлять до истечения с вероятностью

### Invalidation стратегии
- [ ] **Write-through** — обновлять кеш сразу после записи в БД
- [ ] **Time-based** — подходит для eventually consistent данных
- [ ] **CancellationToken** — `AddExpirationToken` для ручной инвалидации групп

## 6. Асинхронность и параллелизм

### ValueTask vs Task
- [ ] **Task по умолчанию** — безопаснее, можно await несколько раз
- [ ] **ValueTask для hot paths** — когда часто sync completion (кеш, буферы). Нельзя await дважды
- [ ] **Профилировать перед переходом** — экономия ~50 байт на операцию

### ConfigureAwait
- [ ] **`.ConfigureAwait(false)` в библиотеках** — предотвращает deadlock у потребителей
- [ ] **НЕ нужен в ASP.NET Core** — нет SynchronizationContext
- [ ] **ConfigureAwaitOptions (.NET 8+)** — `SuppressThrowing` и другие опции

### Channel<T>
- [ ] **Bounded channel для backpressure** — `BoundedChannelOptions(100)`, `FullMode.Wait`
- [ ] **`SingleReader/SingleWriter`** — оптимизация если один consumer/producer
- [ ] **`ReadAllAsync` + `await foreach`** — идиоматичный consumer loop

### Parallel.ForEachAsync
- [ ] **Явно задавать MaxDegreeOfParallelism** — для предсказуемости
- [ ] **ProcessorCount для CPU-bound** — больше для I/O-bound
- [ ] **Передавать CancellationToken** — для graceful shutdown

### IAsyncEnumerable
- [ ] **`[EnumeratorCancellation]`** — для правильной работы `WithCancellation()`
- [ ] **Streaming вместо ToListAsync** — меньше памяти для больших результатов
- [ ] **yield return в async** — для streaming API

## 7. Сериализация

### System.Text.Json Source Generators
- [ ] **`[JsonSerializable(typeof(T))]`** — для каждого сериализуемого типа
- [ ] **`JsonSerializerContext` singleton** — `AppJsonContext.Default.MyType`
- [ ] **Избегать reflection mode** — `JsonSourceGenerationOptions(UseReflectionDefault = false)`
- [ ] **40% быстрее startup** — меньше binary size при trimming

### AOT-совместимость
- [ ] **Generic enum converter** — `[JsonConverter(typeof(JsonStringEnumConverter<Status>))]`
- [ ] **Избегать Type.MakeGenericType** — в custom converters
- [ ] **Тестировать с PublishAot** — ловить проблемы рано

### Миграция с Newtonsoft.Json
- [ ] **JObject → JsonDocument/JsonNode**
- [ ] **JsonConvert → JsonSerializer**
- [ ] **Кастомные converters** — `JsonConverter<T>` base class

### Альтернативные сериализаторы
- [ ] **MessagePack** — 10x быстрее JSON для internal communication
- [ ] **Protobuf** — для gRPC, schema validation, cross-platform
- [ ] **Встроенная LZ4 компрессия** — в MessagePack

## 8. Dependency Injection

### Keyed Services (.NET 8+)
- [ ] **`AddKeyedScoped<IService, Impl>("key")`** — вместо custom factories
- [ ] **`[FromKeyedServices("key")]`** — инжекция по ключу
- [ ] **IKeyedServiceProvider** — для динамического разрешения

### Выбор Lifetime
- [ ] **Singleton** — для stateless, thread-safe, expensive init. Минимум GC pressure
- [ ] **Scoped** — для DbContext, request state. Один instance per request
- [ ] **Transient** — для lightweight stateless. Новый instance каждый раз

### Captive Dependencies
- [ ] **Включить ValidateScopes в Dev** — `options.ValidateScopes = true`
- [ ] **IServiceScopeFactory в Singleton** — для доступа к scoped services
- [ ] **Правило: Singleton → только Singleton** — scoped в singleton = captive dependency

### Factory Delegates
- [ ] **Использовать для conditional создания** — на основе runtime config
- [ ] **`Func<IService>` для lazy** — отложенное создание
- [ ] **Избегать Service Locator** — `GetService()` скрывает зависимости

## 9. Строки и текст

### string.Create
- [ ] **Для известной длины** — `string.Create(len, state, (span, s) => { ... })`
- [ ] **Zero-allocation** — пишем прямо в результирующий buffer
- [ ] **Для конкатенации** — когда известны все части

### StringBuilder Pooling
- [ ] **ObjectPool<StringBuilder>** — `DefaultObjectPoolProvider().CreateStringBuilderPool()`
- [ ] **Return в finally** — policy автоматически очищает

### StringComparison
- [ ] **Ordinal для internal** — самый быстрый, binary comparison
- [ ] **OrdinalIgnoreCase** — case-insensitive без culture overhead
- [ ] **Избегать CurrentCulture** — медленно, непредсказуемо

### Span-based Parsing
- [ ] **`int.Parse(span)`** — без substring аллокаций
- [ ] **`span.Slice()` вместо Substring** — zero-copy
- [ ] **`TryFormat` в Span** — форматирование без string аллокации

### CompositeFormat (.NET 8+)
- [ ] **`CompositeFormat.Parse(template)`** — pre-parse один раз
- [ ] **`string.Format(culture, compositeFormat, args)`** — 15-30% быстрее repeated formatting

## 10. HTTP клиенты

### IHttpClientFactory
- [ ] **Всегда использовать Factory** — правильный lifecycle, connection pooling
- [ ] **Named или Typed clients** — конфигурация в одном месте
- [ ] **НЕ new HttpClient()** — socket exhaustion, DNS caching issues

### SocketsHttpHandler
- [ ] **`PooledConnectionLifetime = 2-15 min`** — принудительный DNS refresh
- [ ] **`PooledConnectionIdleTimeout`** — очистка idle connections
- [ ] **`MaxConnectionsPerServer`** — tune под нагрузку
- [ ] **`SetHandlerLifetime(Infinite)`** — когда сами управляем через SocketsHttpHandler

### Resilience (Polly v8)
- [ ] **`AddStandardResilienceHandler()`** — retry + circuit breaker + timeout из коробки
- [ ] **`UseJitter = true`** — randomization для избежания thundering herd
- [ ] **Custom pipeline** — `AddResilienceHandler()` для fine-tuning

## 11. Логирование

### Source Generated Logging
- [ ] **`[LoggerMessage]` атрибут** — compile-time оптимизация, no boxing
- [ ] **partial методы в partial class** — `private partial void LogOrderProcessed(int orderId)`
- [ ] **Статические extension методы** — `public static partial void LogX(this ILogger, ...)`

### High-Performance Patterns
- [ ] **Избегать $"" в log calls** — аллокация даже если level выключен
- [ ] **`IsEnabled(LogLevel)` перед expensive операциями** — `if (_logger.IsEnabled(Debug))`
- [ ] **Strongly-typed параметры** — избегает boxing value types
- [ ] **CA1848 analyzer** — предупреждает о performance issues

### LoggerMessage.Define (legacy)
- [ ] **Static readonly Action** — template парсится один раз
- [ ] **Для .NET 5 и ниже** — где нет source generators

## 13. Конфигурация и Startup

### Минимизация Startup Time
- [ ] **ReadyToRun (R2R)** — `<PublishReadyToRun>true</PublishReadyToRun>`. Pre-compiled native code
- [ ] **Tiered Compilation включен** — по умолчанию в .NET Core 3+
- [ ] **Lazy<T> для expensive сервисов** — создание при первом использовании
- [ ] **BackgroundService для warm-up** — кеши, подключения после старта

### Options Pattern
- [ ] **`IOptions<T>`** — singleton, fastest, no reload. Для static config
- [ ] **`IOptionsMonitor<T>`** — singleton с reload. Для singletons нужен refresh
- [ ] **`IOptionsSnapshot<T>`** — scoped, reload per request. ~100μs overhead
- [ ] **`ValidateOnStart()`** — fail fast при невалидной конфигурации

### Configuration Performance
- [ ] **Bind один раз через Options** — не читать `IConfiguration` в hot path
- [ ] **`reloadOnChange: true`** — только если нужен hot reload
- [ ] **POCO binding** — типизированная конфигурация быстрее dictionary lookup

## Быстрая таблица: когда что использовать

| Сценарий | Рекомендация | Выигрыш |
|----------|--------------|---------|
| Временный буфер >1KB | `ArrayPool<T>.Shared` | До 850x быстрее |
| Буфер <256 байт | `stackalloc` | Stack speed, zero GC |
| Async буфер | `MemoryPool<T>` | Pooling + async |
| Lookup table | `FrozenDictionary` | 50% быстрее read |
| Частый string search | `SearchValues<T>` | 4-7x быстрее |
| JSON сериализация | Source generators | 40% быстрее startup |
| Internal serialization | MessagePack | 10x быстрее JSON |
| Read-only EF query | `AsNoTracking()` | 20-40% быстрее |
| Bulk update/delete | `ExecuteUpdateAsync` | 10x+ быстрее |
| High-throughput DB | DbContext Pooling | 5.5x быстрее |
| Кеш с L1+L2 | `HybridCache` | Stampede protection |
| Hot path variadic | `params ReadOnlySpan<T>` | Zero allocation |
| Логирование | `[LoggerMessage]` | No boxing, compile-time |

5. [ ] Использовать **IHttpClientFactory** вместо `new HttpClient()`
6. [ ] Включить **`[LoggerMessage]`** source generator для логов
7. [ ] Использовать **ArrayPool** для временных буферов
8. [ ] **FrozenDictionary** для static lookup tables

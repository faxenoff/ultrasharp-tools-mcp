# UltrasharpTools MCP Server

**Ultra-fast MCP server enabling AI agents to comprehensively work with C# solutions: instant structural search, code modification with automatic linting/formatting/fixes, static debugging and backwards crash analysis, integrated Git automation.**

**Version:** 3.2.0 | **Framework:** .NET 10.0 | **Status:** Production Ready

---

## CRITICAL: Proactive MCP Tools Usage

**When working with C# code in this project, use SharpTools MCP FIRST, not as last resort.**

### Quick Decision Tree:

```
ANY C# task? -> Use MCP tools IMMEDIATELY
|- Understanding code? -> LoadSolution + LoadProject (30 sec vs 30 min)
|- Don't know exact class name? -> pattern_search or semantic_search
|- Need to modify? -> modify_code / add_member (auto-linting included!)
|- Debugging crash? -> trace_backwards + analyze_logs (15 sec vs 30 min)
|- Code quality? -> format_code + analyze_code_style + apply_code_fixes
```

### Key Rules:
1. **ALWAYS** start with `load_solution`
2. **USE semantic search** when you don't know FQN: `semantic_search`, `pattern_search`
3. **DON'T read manually** what MCP can do in seconds (10-100x faster)
4. **TRUST auto-linting** - every modification includes quality checks
5. **5 log formats** supported: ECS/JSON, Logcat, WebServer, XML, PlainText

## Project Overview

UltrasharpTools is a production-ready MCP server for C# codebases powered by Roslyn. Provides AI agents with IDE-level tools for analysis, modification, and debugging.

### Key Features:
- **FastSymbolIndex** - 10-100x faster symbol lookup (O(1) via Bloom filter + FrozenDictionary)
- **Parallel Indexing** - 2-4x speedup via dependency-level parallel compilation
- **50+ MCP tools** - analysis, modification, debugging, quality
- **Git automation** - auto branches, commits, undo
- **Quality Tools** - CSharpier, Roslyn analyzers, auto-fixes
- **Advanced Tracing** - static execution flow, backtrace with Z3 SMT solver
- **Semantic Search** - vector-based code similarity (via external VectorDB)

## Quick Start for Developers

### 1. Build & Run

```bash
# Debug build
dotnet build UltrasharpTools.sln

# Release build
dotnet build UltrasharpTools.sln -c Release

# Optimized publish (Droid)
pwsh Dev.Scripts/publish-mcp.ps1

# Hybrid publish (Droid + VectorDB)
pwsh Dev.Scripts/publish-hybrid.ps1
```

### 2. Run Servers

```bash
# Stdio server (local MCP)
cd UltrasharpTools.Droid
dotnet run -- --log-level Information

# HTTP SSE server (remote MCP)
cd UltrasharpTools.Overlord
dotnet run -- --port 3001 --log-level Information

# VectorDB (Indexer)
cd UltraSharpTools.VectorDB
dotnet run -- --port 11435
```

### 3. Command Line Options

| Option | Description |
|--------|-------------|
| `--log-level <level>` | Verbose, Debug, Information, Warning, Error, Fatal |
| `--load-solution <path>` | Pre-load solution at startup |
| `--build-configuration <cfg>` | Debug or Release |
| `--disable-git` | Disable Git integration |

## Architecture Highlights

### Logging Pattern

All services use partial class pattern for source-generated logging:

```csharp
// MyService.cs
public sealed partial class MyService
{
    public void DoWork() => LogStarted("operation");
}

// MyService.Logging.cs
public sealed partial class MyService
{
    [LoggerMessage(EventId = 1000, Level = LogLevel.Information,
        Message = "Started: {Name}")]
    private partial void LogStarted(string name);
}
```

## Development Guidelines

### Adding New Tools

1. Add method to appropriate `*Tools.cs` with `[DroidTool]` and `[Description]`
2. Use DI for services
3. Wrap in `ErrorHandlingHelpers.ExecuteWithErrorHandlingAsync`
4. Add logging to `.Logging.cs` partial

### Adding New Services

1. Create interface in `Interfaces/`
2. Implement in `Services/`
3. Create `.Logging.cs` partial class
4. Register in `ServiceCollectionExtensions`

### Version Update

```bash
# Preview changes
Dev.Scripts\update-version.cmd 3.3.0 --dry-run

# Apply changes
Dev.Scripts\update-version.cmd 3.3.0
```

Updates 21 locations: .csproj, Dockerfile, Program.cs, Chart.yaml, docs.
